02

What changed — before & after

The substance of the overhaul, grouped by area. The left of each row is how it behaved when we started; the right is how it behaves now.

Teacher & student login by email Phase 1

Before

Adding a teacher or student created only a profile row — no login account at all. Those people could never sign in. Login accepted a username only, never an email.

After

Adding a teacher (by admin) or student (by teacher) auto-creates a login account from the email entered. Users sign in with that email or a username, and the created account shows its login + password in a toast.

Forced first-login password change Phase 1

Before

No concept of temporary passwords or first-login setup existed.

After

New accounts get the default password changeme123 and are taken to a “Set a new password” screen on first login before they can use the app.

Self-signup Phase 1

Before

A public “Create Account” page existed but was broken (it required a username the form never sent) and contradicted its own “admin-added only” note.

After

Self-signup is removed entirely. Accounts exist only when an admin adds a teacher or a teacher adds a student — matching the intended model.

Add Student / Add Teacher forms Phase 2

Before

~13 fields each, including a manually typed ID, dates, guardian details, salary, etc. Editing didn’t pre-fill reliably.

After

Trimmed to essentials — Student: name, email, grade, section; Teacher: name, email, subject. IDs, dates and status are generated server-side. Forms re-initialise correctly on open.

Who creates whom Phase 2

Before

Only admins could create students; teachers saw an Edit button that the backend rejected with a 403.

After

Teachers create students (admins do not); admins create teachers. Add/Edit/Delete buttons now match what each role is actually allowed to do.

Teacher assignments Phase 3

Before

Creating a “Quiz” failed validation. “Toggle Status” called a non-existent endpoint with an invalid status, so it always errored.

After

Assignment types include quiz & test; the button now Activates / Deactivates reliably. Teachers can only create assignments for their own courses.

Grading submissions Phase 3

Before

No grading UI existed, and a backend bug meant teachers saw zero submissions — grading was impossible.

After

A Student Submissions section lets teachers enter a grade + feedback and Save. It records who graded it and when, and marks the work Graded.

Student “My Teachers” & class rank Phase 4

Before

“My Teachers” was requested with the wrong ID (always empty) and never shown on the page. Class Rank was permanently “N/A”.

After

A My Teachers card lists the teachers of the student’s enrolled courses, and real class rank is computed with QuickSort.

Attendance bulk entry Phase 5

Before

The student list never loaded (malformed request), “All Grades” broke it, and the Quick-Actions bar was duplicated.

After

Pick a grade & course → the enrolled students load; All Present / Absent / Late work; one clean action bar; the list stays in sync with the chosen course.

Calendar Phase 5

Before

Showed the wrong year, editing an event created a duplicate, “All grades” crashed the picker, the grid didn’t refresh, and teacher/student filtering used the wrong ID.

After

Correct month/year, edit updates in place, the picker works, the grid refreshes immediately, and each role sees the right events (teachers can create grade-scoped ones).

Notifications Phase 5

Before

The 🔔 bell existed but nothing ever created a notification, so it was always empty.

After

Real notifications fire: enrolled students are notified when a new assignment is posted, and a student is notified when their work is graded.

Algorithms on show Phase 6

Before

QuickSort powered rankings but wasn’t obvious, and there was no dedicated search algorithm — lookups were plain linear filters.

After

A hand-written Binary Search (O(log n)) powers “Quick Lookup by Student ID” and reports the comparison count; QuickSort is labelled on rankings; MergeSort stays as a documented alternative.

Backend access control Phase 7

Before

List endpoints (marks, attendance, enrolments) returned everyone’s data to any logged-in user; teachers could write marks/attendance for any course.

After

Lists are role-scoped (teacher → own courses, student → own records); teacher writes are restricted to their own courses; duplicate errors read as friendly messages.

Verification Phase 8

Before

Changes were spread across many files with no consolidated check.

After

All 17 changed source files pass a clean syntax check; the full manual test plan below covers every new behaviour.

04

New features added

Capabilities that did not exist before this work, distinct from bug fixes.

  • Email-based accounts auto-provisioned when an admin adds a teacher or a teacher adds a student.
  • Forced first-login password change flow with its own screen.
  • Simplified add-student and add-teacher forms with server-generated IDs and defaults.
  • Teacher grading workspace — view student submissions, enter grade + feedback, save.
  • Student “My Teachers” directory and a live class rank.
  • Working attendance bulk entry with All-Present/Absent/Late shortcuts.
  • Editable calendar with role-aware event visibility.
  • In-app notifications for new assignments and grades.
  • Binary Search “Quick Lookup by Student ID” with a live comparison count, plus labelled QuickSort rankings — the educational algorithm showcase.
  • Role-scoped, ownership-checked API — the security layer that makes the three panels genuinely separate.

Detailed test plan

Run these in order after npm run db:push and a restart. Use a private/incognito window (or log out between roles) so sessions don’t overlap.

Admin admin / admin123

  1. Log in as admin. the Dashboard opens; its top button says Add Teacher (no “Add Student”).
  2. Open Teachers → Add New Teacher. Enter first/last name, a real email (e.g. tara.k@school.edu) and a subject; Save. a toast shows Login: tara.k@school.edu / changeme123; the teacher appears with an auto ID like TCH-0011.
  3. Confirm there is no way to add a student as admin (no Add button on Students). admin can view/manage but not create students.
  4. Try adding a second teacher with the same email. a friendly “an account with this email already exists” message, not a crash.
  5. Go to Courses, create a course and leave the teacher unassigned. it saves (no foreign-key error) and shows “Unassigned”.

Teacher the email you just created

  1. Log out, then log in with the new teacher’s email and changeme123. you land on the Set a new password screen.
  2. Set a new password (≥ 6 chars, both fields matching). you proceed into the Teacher Panel; next login uses the new password.
  3. Also confirm the seeded teacher works: log in as ram_teacher / teacher123 (no forced change — existing account).
  4. In the Teacher Panel, Create Assignment for one of your courses, type Quiz. it saves successfully (no validation error).
  5. On that assignment, click Deactivate, then Activate. the status flips each time with no error.
  6. Go to Students → Add New Student, enter name, email, grade, section; Save. toast shows the student’s login + changeme123; auto ID like STU-0301.
  7. Open Attendance → Mark Attendance: choose a grade, then a course. the enrolled students list appears; All Present/Absent/Late set every row; Save records them.
  8. After a student submits (below), open the Student Submissions card, enter a grade + feedback, click Save. the row flips to Graded.

Student STU-0001 / student123

  1. Log in as a seeded student in one of the test teacher’s courses (e.g. STU-0001). the Student Panel shows a numeric Class Rank (not “N/A”) and a My Teachers card listing that course’s teacher(s) with email.
  2. Open an assignment and Submit some text. it moves to “Submitted”; the teacher can now grade it (step above).
  3. After the teacher grades it, refresh the panel. the submission shows the grade, and the 🔔 bell shows an “Assignment graded” notification.
  4. When the teacher posts a new assignment to your course, check the bell. a “New assignment posted” notification appears.

Cross-cutting algorithms, calendar, security

  1. Binary Search: as admin/teacher on Students, use “Quick Lookup by Student ID” with a real ID like STU-0001. it finds the student and shows a badge like “Found in 4 comparisons”; a bad ID (STU-9999) reports not found with the count.
  2. QuickSort: open Marks & Rankings. the rankings table carries a “Ranked with QuickSort algorithm” label.
  3. Calendar edit: add an event, then click it and change the title; Save. it updates in place — no duplicate — and the grid refreshes.
  4. Calendar “All grades”: open the event dialog’s grade dropdown and choose “All grades”. the picker works (no crash) and the event is created as a global event.
  5. Isolation: while logged in as a teacher, confirm you see only your own courses’ students, marks and attendance — not the whole school.
